# รายงานสรุปภาพรวมและสถาปัตยกรรม — Cable Calculator

> เอกสารนี้อธิบายภาพรวมและการตัดสินใจเชิงวิศวกรรมของเว็บแอปออกแบบระบบไฟฟ้า เพื่อใช้อ้างอิงและเผยแพร่ต่อสาธารณะ โดยไม่เปิดเผยซอร์สโค้ด สูตรและตารางมาตรฐานที่ใช้คำนวณ ข้อมูลผู้ใช้ ที่อยู่ของระบบ หรือค่าตั้งค่าใดๆ ซึ่งเป็นทรัพย์สินของผู้ว่าจ้าง

## 1. ภาพรวม

Cable Calculator เป็นเว็บแอปสำหรับวิศวกรและผู้ออกแบบระบบไฟฟ้าในอาคาร ผู้ใช้สร้างแบบจำลองของอาคารขึ้นในระบบ แล้วให้ระบบช่วยคำนวณโหลด จัดวงจรย่อยเข้าแผงควบคุม เลือกขนาดสายไฟ และออกเป็นรายงานที่พิมพ์ส่งงานได้

## 2. แนวคิดหลัก: จำลองอาคารก่อน แล้วค่อยคำนวณ

เครื่องมือคำนวณงานวิศวกรรมส่วนใหญ่เป็นฟอร์มให้กรอกตัวเลขแล้วกดคำนวณ ซึ่งใช้ได้กับโจทย์เดี่ยวๆ แต่พังเมื่อต้องออกแบบทั้งอาคาร เพราะตัวเลขชุดเดียวกันถูกใช้ซ้ำในหลายจุด และเมื่อแก้ที่จุดหนึ่งก็ต้องไล่แก้ตามทุกจุดด้วยมือ

ระบบนี้เลือกอีกทาง คือให้ผู้ใช้ **สร้างโครงสร้างของอาคารขึ้นมาก่อน**

```text
ประเภทอาคาร → ชั้น → ห้อง → อุปกรณ์และโหลดในห้อง
                              ↓
                    โหลดรวมของห้องและชั้น
                              ↓
                    วงจรย่อย → แผงควบคุม
                              ↓
                    ขนาดสายไฟ → รายงาน
```

ทุกการคำนวณอ้างอิงแบบจำลองชุดเดียว ผลลัพธ์ปลายทางจึงเป็นค่าที่คำนวณจากต้นทางเสมอ ไม่ใช่ตัวเลขที่ผู้ใช้กรอกซ้ำไว้คนละที่ เมื่อแก้โหลดในห้องหนึ่ง วงจร แผง ขนาดสาย และรายงานจะสะท้อนการแก้นั้นทั้งสาย

ผลที่ตามมาคือ **ความถูกต้องของแบบจำลองสำคัญกว่าความถูกต้องของหน้าจอใดหน้าจอหนึ่ง** งานส่วนใหญ่ของโปรเจกต์จึงอยู่ที่การออกแบบโครงสร้างข้อมูลและการจัดการสถานะ ไม่ใช่ที่สูตรคำนวณ

## 3. การจัดการสถานะของโครงสร้างที่ซ้อนกันหลายชั้น

ข้อมูลของอาคารหนึ่งหลังซ้อนกันลึกและแก้ไขได้จากหลายหน้าจอ ระบบจึงเก็บสถานะไว้ที่ส่วนกลางด้วย Recoil พร้อมคงสถานะไว้ข้ามการรีเฟรชหน้า

เหตุผลที่ต้องคงสถานะไว้คือพฤติกรรมของผู้ใช้จริง งานออกแบบอาคารหนึ่งหลังใช้เวลาหลายชั่วโมงและทำไม่จบในรอบเดียว ถ้าเผลอปิดแท็บแล้วงานหายทั้งหมด เครื่องมือนั้นจะไม่ถูกใช้ซ้ำ

## 4. แผงควบคุมและวงจรย่อย

- สร้างและแก้ไขแผงควบคุมไฟฟ้า
- จัดวงจรย่อยเข้าแผง และแก้ไขได้รายวงจร
- คำนวณวงจรย่อยและเลือกขนาดสายไฟจากโหลดที่ได้จากแบบจำลอง

ส่วนนี้เป็นจุดที่ผู้ใช้ปรับแต่งมากที่สุด เพราะการจัดวงจรมีทางเลือกหลายแบบที่ถูกต้องทั้งหมด ระบบจึงเสนอค่าที่คำนวณได้ให้ก่อน แล้วเปิดให้ผู้ใช้ปรับ แทนที่จะบังคับผลลัพธ์เพียงทางเดียว

## 5. รายงานคือผลลัพธ์จริงของงาน

งานออกแบบระบบไฟฟ้าไม่ได้จบที่หน้าจอ แต่จบที่เอกสารที่ส่งให้ผู้ว่าจ้างหรือผู้ตรวจแบบ ระบบจึงมีส่วนจัดหน้าสำหรับพิมพ์แยกจากหน้าจอใช้งานปกติ และสร้างไฟล์ PDF ได้

การแยกส่วนรายงานออกมาเป็นของตัวเองมีเหตุผลทางเทคนิค คือหน้าจอใช้งานออกแบบมาเพื่อการแก้ไข มีปุ่มและส่วนควบคุมที่ไม่ควรติดไปในเอกสาร ส่วนรายงานต้องควบคุมขนาดหน้า การตัดหน้า และลำดับของเนื้อหาได้แน่นอน สองอย่างนี้มีข้อกำหนดคนละชุดกัน การใช้หน้าจอเดียวกันแล้วซ่อนบางส่วนตอนพิมพ์ จะทำให้ทั้งสองฝั่งแก้ยากในระยะยาว

นอกจากนี้ยังมีแผนภูมิสรุปผลหลายรูปแบบ เพื่อให้เห็นภาพรวมของการกระจายโหลดโดยไม่ต้องอ่านตาราง

## 6. รองรับสองภาษา

ทั้งหน้าจอและรายงานรองรับภาษาไทยและอังกฤษ โดยแยกข้อความทั้งหมดออกจากโค้ด

จุดที่มักถูกมองข้ามคือ **เอกสารก็ต้องแปลด้วย** ไม่ใช่แค่หน้าจอ เพราะรายงานคือสิ่งที่ถูกส่งออกไปนอกองค์กร และผู้รับอาจคนละภาษากับผู้ออกแบบ

## 7. บัญชีผู้ใช้

มีระบบสมัครสมาชิก เปิดใช้งานบัญชี ตั้งรหัสผ่านใหม่ แก้ไขโปรไฟล์ และหน้าจัดการการเรียกเก็บเงิน เนื่องจากผู้ว่าจ้างให้บริการเครื่องมือนี้แบบมีค่าใช้จ่าย

## 8. บทเรียนที่ได้

1. **เครื่องมือคำนวณที่ดีเริ่มจากแบบจำลอง ไม่ใช่จากฟอร์ม** การให้ผู้ใช้อธิบายสิ่งที่เขากำลังออกแบบก่อน ทำให้แก้ไขและตรวจทานง่ายกว่าการกรอกตัวเลขทีละช่อง
2. **เอกสารคือผลลัพธ์ ไม่ใช่ของแถม** ถ้าปลายทางของงานคือไฟล์ที่ส่งให้คนอื่น ส่วนออกเอกสารต้องถูกออกแบบจริงจังเท่ากับหน้าจอ
3. **งานที่ทำยาวหลายชั่วโมงต้องไม่หาย** การคงสถานะไว้ให้ผู้ใช้กลับมาทำต่อได้ เป็นฟีเจอร์ที่ตัดสินว่าเครื่องมือจะถูกใช้ซ้ำหรือไม่
